## OBJECTIVE

Harden the read-only display states of the public Product Detail route
(`/products/[id]`) introduced in TOPLINE-P2-004. Add a route-level loading
skeleton, a route-level error boundary, and explicit unavailable-data states
for missing category, missing specifications, and missing related products —
without changing business logic, data sources, or any non-UI surface.

## FILES CREATED

### `src/app/products/[id]/loading.tsx`
- Route-level read-only loading skeleton (Next.js App Router convention)
- Renders inside `AppShell` with the same breadcrumbs as the real page
- Mirrors the page's shape: media column, info column (category, title, vendor,
  price, rating, stock badge, CTA placeholders, trust block), specs table
  placeholder, related-products grid placeholder
- Uses the project's existing design tokens (`--surface-muted`, `--text-muted`)
- Animated via `animate-pulse`; all blocks `aria-hidden="true"` so screen
  readers don't read skeleton text
- Container exposes `role="status"`, `aria-live="polite"`, and an
  `aria-label="Loading product details"` for assistive tech

### `src/app/products/[id]/error.tsx`
- Route-level client error boundary (Next.js App Router convention;
  must be `"use client"` to receive `reset()`)
- Renders inside `AppShell` with the same breadcrumbs
- Headline: "We couldn't load this product"
- Body copy explains the failure and offers two recovery paths:
  - **Try again** — calls `reset()` to re-render the segment
  - **Browse all products** — `Link` to `/products`
- Surfaces `error.digest` in monospaced muted text for support diagnostics
- `role="alert"`, `aria-live="assertive"`
- Logs the digest client-side only when present; never leaks raw error text

## FILES MODIFIED

### `src/app/products/[id]/page.tsx`
- Added `import { EmptyState } from "@/components/ui/EmptyState"` (reusing the
  project's existing component — no new dependency)
- **Not Found state** — replaced inline JSX block with `EmptyState` using a
  magnifier icon, expanded copy explaining why a product may be unavailable
  (removed / renamed / bad link), and a "Browse all products" recovery action
- **Category unavailable** — when a found product's `categoryId` cannot be
  resolved, render a muted italic "Category unavailable" line in place of the
  category name (was silently absent)
- **Specifications unavailable** — when `product.specifications` is empty or
  missing, render an `EmptyState` (document icon, "Specifications unavailable")
  in place of the table (was silently absent)
- **No related products** — when the category has no siblings, render an
  `EmptyState` (cart icon, "No related products yet") with a "Browse all
  products" action (was silently absent)
- **Image fallback** — kept the existing inline "No image available" fallback
  inside the media container (already explicit, no change)
