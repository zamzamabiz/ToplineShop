## 5. ADR-TDR-001 — MVP User and First Use Case

### Decision

**Status:** CLOSED

**MVP User:** An authorized operations reviewer — a tenant member holding `tdr.view` and `tdr.quarantine.review` permissions — who is responsible for processing and approving supplier/product trade rows submitted by a trusted supplier. The reviewer does not write raw values; they inspect source records, validate normalized outputs, resolve quarantined exceptions with attributable decisions, and confirm publication into the canonical product trade line.

**Why this user:**
- Directly maps to the roadmap's "narrow, proven vertical slice" objective.
- Scope-limited: can view and review but cannot autonomously correct financial, pricing, or identity fields without separate permission (`tdr.correction.approve`).
- Tenant-scoped: reviewer operates within their own tenant context and cannot cross tenant boundaries.
- Represents the operator role with the highest decision-authority in the MVP review workflow before `tdr.canonical.publish` executes.

**Primary journey — "Inspect, Review, and Confirm a Supplier Trade Import":**

1. Reviewer opens the TDR module and navigates to Sources.
2. Reviewer selects the approved source profile (e.g., "SUPPLIER_TRADE_LINES_V1") and inspects the schema version, mapping version, and last-run summary.
3. A new import batch has arrived and is in RECONCILING state. Reviewer opens the Batch Detail and reviews the count summary: total rows received, accepted, quarantined, rejected.
4. Reviewer navigates to the Quarantine Queue and filters by severity ERROR.
5. For each queued record, the Record Review surface shows original row, normalized output, validation findings (rule code, severity, field, reason), and proposed corrected values.
6. Reviewer approves eligible corrections, rejects unresolvable records with a documented reason, or returns ambiguous records for further investigation.
7. Once quarantine queue is cleared or accepted below configured threshold, batch transitions to COMPLETED.
8. Reviewer confirms in the Lineage View that published records trace back to the source batch, raw artifact, and mapping version.
9. Reviewer reviews the Quality Report for pass/fail rates by rule and confirms reconciliation totals match: input rows = accepted + quarantined + rejected.

**Acceptance conditions for this journey:**
- Every quarantine decision captures actor, tenant, action, reason, and timestamp.
- Every published record has a stable canonical identifier and a lineage link.
- Replaying the same source file with the same idempotency key produces zero unintended duplicates.
- Batch counter reconciliation is enforced before COMPLETED state.

## 6. ADR-TDR-002 — First Source Format and Exact Schema

### Decision

**Status:** CLOSED

**First source format:** UTF-8 CSV with a fixed, explicitly documented header row. No BOM. Line ending: `\n` (LF). Quote character: `"`. Escape: `""` (double-quote). Maximum file size: 10 MB (subject to approved envelope limit). Maximum rows per batch: 50,000 (subject to approved row limit). Header row is row 1; data begins at row 2.

**Source profile name (synthetic):** `SUPPLIER_TRADE_LINES_V1`

**Source schema version:** `v1.0`

### Exact Header Specification (Synthetic — Non-Sensitive)

| Column # | Header | Type | Required | Canonical target | Notes |
|---|---|---|---|---|---|
| 1 | `source_id` | string | Yes | `TdrImportRecord.sourceKey` | Stable row identifier from source system |
| 2 | `supplier_code` | string | Yes | `TdrCanonicalRecord.supplierCode` | Must match approved vendor reference |
| 3 | `product_sku` | string | Yes | `TdrCanonicalRecord.productSku` | Source product identifier |
| 4 | `product_name` | string | Yes | `TdrCanonicalRecord.productName` | Description; max 255 chars |
| 5 | `category_code` | string | No | `TdrCanonicalRecord.categoryCode` | Optional reference code |
| 6 | `unit_price` | decimal string | Yes | `TdrCanonicalRecord.unitPrice` | Positive decimal; max 2dp; no currency symbol |
| 7 | `currency_code` | string | Yes | `TdrCanonicalRecord.currencyCode` | ISO 4217 three-letter code (e.g., `GBP`) |
| 8 | `quantity_available` | integer string | Yes | `TdrCanonicalRecord.quantityAvailable` | Non-negative integer |
| 9 | `unit_of_measure` | string | Yes | `TdrCanonicalRecord.unitOfMeasure` | Controlled value: `EA`, `KG`, `L`, `M`, `M2`, `M3`, `BOX`, `PKT` |
| 10 | `effective_date` | date string | Yes | `TdrCanonicalRecord.effectiveDate` | `YYYY-MM-DD`; must not be future by > 30 days |
| 11 | `expiry_date` | date string | No | `TdrCanonicalRecord.expiryDate` | `YYYY-MM-DD`; must be ≥ `effective_date` if present |
| 12 | `country_of_origin` | string | No | `TdrCanonicalRecord.countryOfOrigin` | ISO 3166-1 alpha-2 (e.g., `GB`, `DE`) |
| 13 | `is_active` | boolean string | Yes | `TdrCanonicalRecord.isActive` | Accepted values: `true`, `false` (case-insensitive) |
