## Sensitive-Data / PII Sanitization Policy

**Status: POLICY CONTRACT ONLY — does not implement TDR audit service.**

### Mandatory TDR Audit Privacy Rules

1. **No raw file contents** — Never store uploaded file bytes, file content, or CSV/Excel data in audit metadata.
2. **No raw row payloads** — Never store complete trade row objects in audit metadata.
3. **No importer/exporter identities** — Do not store full legal names, registration names, or trade entity names unless PM-classified as non-sensitive.
4. **No address data** — Do not store street addresses, city/province/country unless required for routing and PM-approved.
5. **No contact identifiers** — Do not store phone numbers, email addresses, or any direct contact information.
6. **No tax/regulatory identifiers** — Do not store NTN (National Tax Number), CNIC, STRN, GST registration numbers, or equivalent national IDs.
7. **No financial data** — Do not store bank account numbers, payment instrument details, invoice amounts, or transaction values.
8. **Use references instead of values** — Store `batchId`, `rowIndex`, `fieldKey`, `ruleCode`, `errorCode`, `fileHash`, and `status` instead of raw field values.
9. **Use hashes for corrections** — For corrected field values, store SHA-256 hashes or redacted summaries, never old/new raw values.
10. **Use rule codes for failures** — For validation failures, store `ruleCode`, `severity`, `fieldKey`, `rowIndex`, and `reasonCode` — never the actual field value that failed.
11. **Masked values require PM approval** — If a masked value (e.g., last 4 digits) must appear in logs, it requires explicit PM sign-off per field type.
12. **JSON-safe and size-bounded** — All metadata must be JSON-serializable; metadata objects must be bounded to prevent unbounded log growth (recommended maximum: 2 KB per audit record; exact limit requires PM approval before TDR-P3 implementation).
13. **System actor for automated events** — For automated pipeline events (file hashing, parsing, validation), `actorUserId` must be null and metadata must include a `systemActor` key set to a fixed pipeline identifier.

### SENSITIVE_KEYS Extension Required

The current `sanitizeMetadata()` SENSITIVE_KEYS list must be extended for TDR before TDR audit service implementation:

```

'rawRow', 'rowPayload', 'fileContent', 'fileBytes',
'ntNumber', 'ntn', 'cnic', 'strn', 'gstNumber',
'bankAccount', 'iban', 'invoiceValue', 'transactionAmount',
'importerName', 'exporterName', 'legalName',
'phoneNumber', 'emailAddress', 'address'
```

**This extension is FUTURE_TASK_REQUIRED — not a G2 blocker because the metadata contract (above) prevents raw PII at call sites regardless.**
