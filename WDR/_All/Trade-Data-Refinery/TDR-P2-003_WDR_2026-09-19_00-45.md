## Disabled-Tenant Isolation Contract

**Status: PLANNING ONLY — policy defined for future TDR-P3 implementation.**

| Rule | Policy |
|---|---|
| TDR module disabled for tenant | Tenant must not see TDR navigation in frontend |
| TDR API call from disabled tenant | Returns **403 Forbidden** — "Module not enabled for this tenant" |
| Response policy selection | **403 preferred** — consistent with existing guard chain; aligns with JwtAuthGuard(401) → RolesGuard(403) pattern. Existence hiding (404) adds complexity without clear security benefit in an authenticated API. |
| PM decision required | YES — 403 vs 404 policy must be PM-confirmed before TDR-P3 implementation |
| Public/anonymous access to TDR data routes | DENIED — TDR data routes must never use `@Public()` |
| Cross-tenant TDR access | DENIED — tenantId in JWT payload must match request scope; enforced by @RequiresTenantContext() |
| Unauthenticated access | 401 — enforced by existing JwtAuthGuard before TDR-specific checks |
| Frontend-only hiding | INSUFFICIENT — module disablement must be enforced server-side; frontend hiding is UX only |
