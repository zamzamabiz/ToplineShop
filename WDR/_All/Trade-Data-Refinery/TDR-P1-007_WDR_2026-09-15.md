### Step 2 — Configure Import
- 5 mock selection fields (styled `<select>` elements, local state only):
  - Import Type: File Import / API Pull / SFTP Sync / Manual Upload
  - File / API Format: CSV / XLSX / JSON / XML / NDJSON
  - Mapping Profile: 4 options
  - Validation Profile: Strict / Standard / Lenient
  - Expected Record Count: 4 size bands
- Each field is labelled "mock selection" (amber badge).
- Note: no file is uploaded, no API call is made.

### Step 3 — Review
- Summary table of all 8 selections (source name, type, status, import type, format, mapping profile, validation profile, expected count).
- Amber warning: "No data has been submitted. Proceeding shows planned server workflow — no action is triggered."

### Step 4 — Planned Server Processing
- 6-stage pipeline timeline (all marked "Planned" with clock icon):
  1. File / API receive & deduplication (backend storage)
  2. Schema detection & type inference (refinery engine)
  3. Field mapping & column alignment (mapping profile service)
  4. Record validation & quarantine assignment (validation service + queue)
  5. Quarantine review workflow (review API + Auth/RBAC)
  6. Publish to governed data store (G2: Auth/RBAC + database access)
- Server requirement note.
- 6 disabled action buttons (grid layout):
  1. Start Import
  2. Upload File
  3. Validate Records
  4. Submit for Processing
  5. Schedule Import
  6. Cancel & Reset
- All buttons: `disabled`, `aria-disabled="true"`, `title` explains backend requirement.
