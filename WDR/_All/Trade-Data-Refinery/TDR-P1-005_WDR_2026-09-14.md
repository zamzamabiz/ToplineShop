## 8. UX Features Implemented

### Open Review Preview Button
- Added to `TdrQuarantinePanel` when `quarantined > 0` (error + fatal records exist).
- Hidden / absent when no quarantine records exist (empty scenario).
- Label: "Open Review Preview" with `ShieldAlert` icon.
- `aria-expanded` attribute set correctly.
- Full-width styled button matching TDR visual language.

### Quarantine Review Portal Modal
- Portal via `createPortal(…, document.body)` — same pattern as `TdrBatchDetailPanel`.
- `role="dialog"`, `aria-modal="true"`, `aria-labelledby="tdr-qr-title"`.
- Escape key closes modal.
- Focus lands on close button on open.
- Backdrop click closes modal.

### Mock Quarantine Records
Three static record sets, selected by dominant severity in the current scenario:
- **warning-heavy**: 5 records (HS code mismatch, country name variant, date format, unit of measure, currency code)
- **error-heavy**: 4 records (missing required field, invalid country code, duplicate shipment ref, quantity out of range)
- **fatal-heavy**: 3 records (schema validation failure, fatal parse error, multiple required fields missing)

Scenario mapping:
- Healthy → warning-heavy (warning dominant)
- Warning / High Quarantine → error-heavy (error ≥ warning)
- Failed Batch → fatal-heavy (fatal dominant)

### Severity Filter
- Filter buttons: All · Warning · Error · Fatal
- `aria-pressed` on each filter button.
- Active filter highlighted with brand color.

### Search
- Text input with search icon, `aria-label`.
- Searches across: issue type, field affected, source name, original value, suggested value.
- Case-insensitive.

### Empty Filtered State
- When no records match: "No quarantine records match the current filters."
- "Reset filters" action link clears search and severity filter.

### Selected Record Detail
- Click a record in the list → detail panel updates (local React state only, no API call).
- Shows: record ID, batch ID, source name, field affected.
- Original value (red-tinted box) and suggested value (green-tinted box) for visual contrast.
- "Why quarantined" and "Recommended reviewer action" explanation blocks.
- Large-data production note.

### Disabled Future Actions (6 buttons)
All buttons have `disabled` attribute, `aria-disabled="true"`, and `title` explaining the requirement:
1. Accept Suggestion
2. Reject Suggestion
3. Mark for Manual Review
4. Save Decision
5. Export Clean Rows
6. Re-run Validation

Section is labelled "Review Actions — Backend / Auth required".

### Preview-Only / Production Safety Note
- Amber warning banner in modal header: "Synthetic records only — no real trade data is shown."
- Footer: "Preview only — no real review actions are performed."
- Detail panel: "Fetch each record page from the server. Never load all raw quarantine rows into the browser. Full review requires server-side pagination and Auth/RBAC enforcement."

## 10. Mock Records and Selected-Record Behavior

Records are purely synthetic — no real trade/customer/supplier data. Selected record detail updates via local React state (`selectedId`). On filter change that hides the selected record, the detail defaults to the first visible record (or empty placeholder). No network call, no API adapter, no Node filesystem read.
