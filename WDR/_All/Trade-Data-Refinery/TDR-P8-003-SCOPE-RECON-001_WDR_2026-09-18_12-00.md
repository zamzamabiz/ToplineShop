## 6. P8-003 Definition (from Authoritative Source)

### Task ID (when registered)
`TOPLINE-P8-003`

### Title
Authentication Session Lifecycle and Write Endpoint Protection

### Dependency
`TOPLINE-P8-002` — **PASS** (2026-09-18) ✓ prerequisite is met

### Phase
`phase-8` — Database, Authentication, RBAC & Security

### Objective
Authentication and session behavior. P8-003 owns:

1. **Approved auth package installation** (each package requires separate PM approval — see §8 below)
2. **`POST /auth/login`** — email + password credential verification against `User.passwordHash` via the PM-approved hash algorithm; issues access token + refresh token; writes `Session` row; records `auth.login.success` / `auth.login.failure` audit events
3. **`POST /auth/logout`** — validates access token; deletes the `Session` row; records `auth.logout` audit event
4. **`POST /auth/refresh`** — single-use refresh token rotation; replay detection revokes the entire session; records `auth.refresh.success` / `auth.refresh.failure`
5. **`AuthGuard`** as a global NestJS guard with an explicit `PUBLIC` allowlist (per §F decision matrix)
6. **Protection of all four existing write endpoints** (`POST /tenants`, `POST /vendors`, `POST /categories`, `POST /products`) — return 401 when called without a valid token
7. **Public-route allowlist** — health endpoints remain public; write endpoints are protected
8. **Audit redaction/events** — `AuditService.redactMetadata()` strips `*token*`/`*secret*`/`*password*`/`Authorization` header value before any audit write; wire `auth.*` call sites
9. **Login failure safety** — fixed 401 message `"Authentication required"` with no email/userId leak
10. **`User.status === ACTIVE` enforcement** (GAP-17 from the plan)

### Type of Work
Backend — NestJS, auth module, guards, package installation, test coverage
