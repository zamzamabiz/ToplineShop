## DECISIONS, OPEN QUESTIONS, AND CONTRADICTIONS RECORDED

(All carried into the plan's Gap and Decision Register; summarized here for traceability.)

### Resolved by this plan (not requiring PM re-decision)
- Phase 3 §4.4–4.10 vs Phase 4 schema: Phase 3 proposed `Role`, `Permission`, `RolePermission`, `TenantMembershipRole`, `VendorMembership`, `Module`, `TenantModule`; Phase 4 deferred all of them. Plan §F recommends the unified `Membership` + `TenantMembershipRole` model (post-Phase 3 unified direction) for the implementation; no `UserRole` / `StaffRole` table is added (resolves the contradiction GAP-23).
- Phase 3 §4.11 (`AuthAccount` for OAuth) is deferred to a post-Phase 8 phase; Phase 8 is email/password only (resolves GAP-26).
- Phase 3 §4.13 (`ApprovalGate` for financial/AI) is deferred to Phase 9+ (resolves GAP-25).
- Phase 3 §4.8–4.9 (`Module`, `TenantModule`) is deferred to a post-Phase 8 phase (resolves GAP-24).
- `AuditLog.ipAddress` and `AuditLog.userAgent` columns (deferred by Phase 4) are added in P8-002 as a small additive migration (resolves GAP-06).
- `Vendor.ownerId` is kept for back-compat; `VendorMembership` is added in P8-004 (resolves GAP-13).

### Open questions (PM must decide before P8-002 begins)
- HS256 vs RS256 for access tokens (E).
- Access-token lifetime: 15 min default; refresh 30 days (E).
- Single-device vs multi-device sessions (E).
- `POST /auth/switch-tenant` in scope for P8-003 or later (E).
- Email verification required before first login: blocking vs non-blocking (E).
- Account lockout threshold and duration (E; recommendation 5 attempts → 15 min).
- Password reset in scope for P8-005 (E).
- Rate limiting in scope for P8-002/003: `@nestjs/throttler` is the recommendation (E).
- `PrismaService.onModuleInit` connect mode: lazy vs startup (D).
- Production secret store: not in scope for Phase 8; PM must approve before any production deploy (D, E, G, I).

### Contradictions explicitly recorded
- **C1 (Phase 3 vs Phase 4 schema)**: `UserRole` / `StaffRole` (Phase 3) vs `Membership` (Phase 4). Resolution: use `Membership` + `TenantMembershipRole`; do not add `UserRole` / `StaffRole`. (GAP-23)
- **C2 (Phase 3 vs implementation)**: Phase 3 design `AuthAccount` / `Session` / `Role` / `Permission` were never implemented. Resolution: do not call the Phase 3 design "approved" merely because it exists; record Phase 3 design as context-only, and let each new schema addition be a new PM-approved task. (Recorded in §F "Contradictions" + H/GAP-22–26)
- **C3 (frozen boundary)**: `PrismaService.onModuleInit` is empty today. Phase 8 does not change this; any future P8 task that turns on real DB connectivity is PM-gated (D, GAP-15).
