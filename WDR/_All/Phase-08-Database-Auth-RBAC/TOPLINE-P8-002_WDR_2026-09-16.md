### New `Session` model

```prisma
model Session {
  id                 String    @id @default(uuid())
  userId             String    @map("user_id")
  tenantId           String    @map("tenant_id")
  deviceId           String    @map("device_id") @db.VarChar(128)
  refreshTokenDigest String    @map("refresh_token_digest") @db.VarChar(128)
  expiresAt          DateTime  @map("expires_at")
  revokedAt          DateTime? @map("revoked_at")
  revokedReason      SessionRevocationReason? @map("revoked_reason")
  ipAddress          String?   @map("ip_address") @db.VarChar(45)
  userAgent          String?   @map("user_agent") @db.Text
  createdAt          DateTime  @default(now())
  updatedAt          DateTime  @updatedAt

  user   User   @relation(fields: [userId], references: [id])
  tenant Tenant @relation(fields: [tenantId], references: [id])

  @@unique([userId, deviceId])
  @@unique([refreshTokenDigest])
  @@index([userId])
  @@index([tenantId])
  @@index([expiresAt])
  @@map("sessions")
}
```

### Field rationale

| Field | Type / Constraint | Rationale |
|---|---|---|
| `passwordHash` | `String?` `@db.VarChar(255)` | Nullable: credential storage is opt-in. Argon2id encoding typically fits in 96–255 chars. Hashing behavior owned by P8-003. |
| `AuditLog.ipAddress` | `String?` `@db.VarChar(45)` | Nullable: populated by audit callers when known. 45 chars covers full IPv6 textual form. |
| `AuditLog.userAgent` | `String?` `@db.Text` | Nullable: UA strings are unbounded; TEXT avoids arbitrary truncation. |
| `Session.refreshTokenDigest` | `String` `@db.VarChar(128)` `@@unique` | HMAC-SHA256 digest of the refresh-token **secret only** — never a raw refresh token, never the raw secret. 128 chars covers both hex (64) and base64 (44) encodings with headroom. The unique index is a defense-in-depth uniqueness invariant; the refresh-token HOT PATH in P8-003 is by `sessionId` (UUID PK lookup), not by digest. See §"Forward-Looking P8-003 Refresh-Token Contract". |
| `Session.userId` + `Session.deviceId` | `@@unique([userId, deviceId])` | PM policy: multiple devices per user, one revocable session per user/device. New login on same device replaces after revocation (P8-003). |
| `Session.tenantId` | `String` NOT NULL | Required tenant context at the model level — every session pins an active tenant boundary. |
| `Session.expiresAt` | `DateTime` NOT NULL | Refresh-token expiry; P8-003 enforces. |
| `Session.revokedAt` | `DateTime?` NULL | Null = active session; non-null = revoked at that time. |
| `Session.revokedReason` | `SessionRevocationReason?` NULL | Captures WHY (logout vs rotation vs reuse-detected vs admin), enabling audit trails. |
| `Session.ipAddress`, `Session.userAgent` | nullable, same widths as `AuditLog` | Per-session request context, mirroring audit-log context. |
| FK `sessions.user_id → users.id` | `ON DELETE RESTRICT ON UPDATE CASCADE` | Matches existing `memberships` pattern. Soft-delete via `User.deletedAt` remains the primary user-removal path. |
| FK `sessions.tenant_id → tenants.id` | `ON DELETE RESTRICT ON UPDATE CASCADE` | Matches existing pattern. |

## Forward-Looking P8-003 Refresh-Token Contract

This section documents the **forward-looking contract** that the P8-002 storage shape is designed to support. **No auth behavior is implemented in P8-002.** P8-002 only adds the persistence surface; P8-003 will own the actual verification flow.

### Token format

- A refresh token is the opaque string `<sessionId>.<randomSecret>` — a UUID session identifier followed by a dot and a cryptographically random secret.
- The raw token and the raw secret are **never** persisted, logged, written to `AuditLog.metadata`, written to console, or sent to error-reporting sinks.

### Verification flow (P8-003 owns implementation)

1. Parse the submitted refresh token as `<sessionId>.<secret>`.
2. **Lookup hot path**: find the `Session` row by `sessionId` (UUID PK lookup). The digest column is **not** the lookup hot path.
3. Compute `expectedDigest = HMAC-SHA256(serverSecret, secret)`.
4. **Compare** `expectedDigest` to `Session.refreshTokenDigest` using a **timing-safe equality** check (e.g., `crypto.timingSafeEqual`).
5. On match: rotate (issue a new refresh token; revoke the old session with `revokedReason = REFRESH_ROTATION`).
6. On mismatch for an **active** (non-revoked, non-expired) session: treat as replay; revoke that session with `revokedReason = REFRESH_REUSE_DETECTED` and surface a controlled error. (Tune other invalid-input paths — missing row, expired, already-revoked — per P8-003.)
7. On mismatch for a session that is already revoked/expired: still return a controlled error; do not change `revokedReason` (the prior transition is the audit truth).

### What this means for the P8-002 schema

- `Session.id` (UUID PK) is the lookup key for the hot path — `@@index` is unnecessary because the PK is already indexed.
- `Session.refreshTokenDigest` `@@unique` is a **defense-in-depth uniqueness invariant** (no two rows may share a digest). It is NOT used as the lookup hot path.
- `SessionRevocationReason.REFRESH_ROTATION` and `SessionRevocationReason.REFRESH_REUSE_DETECTED` exist so the audit trail records why a session ended.
- `User.passwordHash` (nullable) is for password authentication; the refresh-token contract is independent and does not read or write `passwordHash`.

### What P8-002 explicitly does NOT do

- No login/logout/refresh endpoint, controller, service, or DTO.
- No `AuthGuard`, no JWT issuance, no token generation, no token rotation, no reuse-detection logic.
- No HMAC server secret storage (that is a P8-003 configuration responsibility).
- No logging of raw tokens, secrets, or digests.
- No package installation (Argon2id, JWT, throttler, passport — all P8-003 / P8-004 territory, subject to PM approval).
