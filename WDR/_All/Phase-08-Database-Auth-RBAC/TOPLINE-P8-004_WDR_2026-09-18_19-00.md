## Key Technical Decisions

### Guard registration order
`APP_GUARD` providers execute in registration order. AuthModule registers:
1. `JwtAuthGuard` — validates JWT, checks `@Public()`, throws 401 if unauthenticated
2. `RolesGuard` — checks `@Roles()` metadata, throws 403 if role missing or tenant context absent

`RolesGuard` is NOT exported from `AuthModule` — registered only via `APP_GUARD` token (exporting would cause NestJS validation error).

### JWT `roles` claim (no DB role field)
No `roles` field on `User` or `Membership` in Prisma schema. RBAC is enforced via the `roles: string[]` claim in the JWT payload. The `JwtStrategy.validate()` maps JWT payload → `req.user`.

### HTTP integration test user injection
`overrideGuard(JwtAuthGuard).useClass(TestJwtAuthGuard)` was tried but `APP_GUARD` multi-provider ordering caused `RolesGuard` to run before the override's `req.user` assignment.

**Fix:** Express middleware registered via `app.use()` (runs before all guards in NestJS lifecycle):
```typescript
app.use((req: any, _res: any, next: any) => {
  const testUserHeader = req.headers['x-test-user'];
  if (testUserHeader) {
    req.user = JSON.parse(Buffer.from(testUserHeader, 'base64').toString('utf-8'));
  }
  next();
});
```
Tests encode user as `x-test-user: base64(JSON)`. Middleware sets `req.user` before `JwtAuthGuard` and `RolesGuard` run.
