## OBJECTIVE

Correct and verify the P7-003 observability foundation so failed-request logs cannot expose raw exception details, infrastructure information, tokens, credentials, or sensitive request data.

## ISSUES IDENTIFIED (BEFORE)

| Issue | Location | Problem |
|-------|----------|---------|
| Raw error.message logged | `logging.interceptor.ts:63` | `error: error.message \|\| 'Unknown error'` exposed exception messages |
| Stack traces logged | `all-exceptions.filter.ts:76-78` | `this.logger.error(..., exception.stack)` logged full stack traces |
| User agent logged | `logging.interceptor.ts:48` | User agent string logged (could contain sensitive info) |
| No correlation ID validation | `logging.interceptor.ts:24` | Raw correlation ID used without validation |

## CORRECTIVE ACTIONS

### 1. Logging Interceptor

Updated `backend/src/common/interceptors/logging.interceptor.ts`:
- Replaced `error.message` with safe error classification (`errorCode` based on status code)
- Removed user agent from logs
- Added correlation ID validation (alphanumeric, hyphens, underscores, max 64 chars)
- Invalid correlation IDs replaced with generated UUID
- Logs only: method, url, status, duration, correlationId, errorCode

### 2. Exception Filter

Updated `backend/src/common/filters/all-exceptions.filter.ts`:
- Removed `exception.message` and `exception.stack` from logger.error call
- Logs only error classification: `Unexpected error: INTERNAL_ERROR`
- Request log now uses structured JSON format with safe error code only
- No raw exception details in logs
