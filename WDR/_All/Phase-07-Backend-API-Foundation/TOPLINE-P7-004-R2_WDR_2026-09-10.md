## AUDIT FINDING BEING CORRECTED

From `TOPLINE-P7-004-R1-AUDIT_2026-09-10.md`:

> The script imports the real `CreateTenantDto` after build, but it does not import or
> instantiate the real `TenantsService`. It defines a local `MockTenantsService`, so
> duplicate slug behavior is tested against copied mock logic rather than
> `backend/src/tenants/tenants.service.ts`.

## IMPLEMENTATION

### backend/scripts/test-tenant-create.js — rewritten service test section

1. **Removed** the local `MockTenantsService` class entirely.
2. **Imports the real `TenantsService`** directly from compiled output:
   `require('../dist/tenants/tenants.service')` — no fallback branch. If the build is
   missing or stale, the script throws immediately rather than silently testing a stand-in,
   because verification requires `npm run build` to run first.
3. **Imports the real `CreateTenantDto`** the same way (also no silent fallback now).
4. **Imports the real `ConflictException`** from `@nestjs/common` — the exact class the
   service throws — and asserts `thrown instanceof ConflictException`.
5. **`createMockPrisma()`** builds a call-tracking mock of only the `PrismaService` surface
   the service actually touches (`tenant.findUnique`, `tenant.create`), recording every
   call's arguments in `_calls.findUnique` / `_calls.create` so assertions can check exactly
   what the real service did, not just its return value.
6. **`new TenantsService(mockPrisma)`** — the real class is instantiated directly (its
   constructor is a plain `(prisma) => { this.prisma = prisma }`, verified from the compiled
   output, so no Nest DI container is required for this kind of unit-level test).

### New/changed assertions (service section, tests 11–15)

- `create()` calls `prisma.tenant.findUnique()` with the correct slug
- Successful create calls `prisma.tenant.create()` exactly once and returns the
  `{ ok: true, data: {...} }` envelope from the real `success()` helper
- Duplicate slug: `serviceB.create(dtoB)` called twice — second call is asserted to throw
  an object that is `instanceof ConflictException` (imported from `@nestjs/common`, the same
  class the real service throws), carrying the expected `"already exists"` message
- Duplicate slug does **not** call `prisma.tenant.create()` a second time (call count stays 1)
- Duplicate slug attempt still calls `prisma.tenant.findUnique()` (proves the lookup ran)
- Multiple distinct tenants can be created through the real service; `prisma.tenant.create()`
  called once per distinct tenant
- Second duplicate on a different slug also throws `ConflictException` without incrementing
  `prisma.tenant.create()` calls
- Real service accepts a `plainToInstance(CreateTenantDto, …)` instance end-to-end

DTO validation tests (1–10) are unchanged and continue to exercise the real
`CreateTenantDto` via `class-validator`.
