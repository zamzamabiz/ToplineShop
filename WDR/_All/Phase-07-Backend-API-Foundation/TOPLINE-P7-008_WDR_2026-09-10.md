The only direct runtime change to `backend/package.json` is the four `devDependencies` entries and the new `test` script — **no production runtime dependency was added**.

### `backend/jest.config.js` (new)

- Single Jest project, `ts-jest` preset, `node` test environment, `roots: ['<rootDir>/src']`, `testRegex: '.*\\.spec\\.ts$'`.
- Excludes `node_modules/` and `dist/` to keep the production build output out of test discovery.
- Uses the existing `tsconfig.json` for TypeScript options.
- Deterministic ordering (`randomize: false`) so test runs are reproducible.
- `testTimeout: 10000` — generous bound for service tests; future integration/e2e suites can override per-test.

### `backend/package.json` (modified — script addition only)

- Added `"test": "jest"`. No other `scripts` entry was touched. The pre-existing `smoke` script (HTTP smoke test) and the four `test-*-create.js` evidence scripts remain untouched and continue to work as standalone evidence (P7-004-R2 audit precedent: "do not break existing standalone evidence scripts").

### `backend/src/testing/test.utils.ts` (new — P7-008 foundation)

- Replaces the four per-script `createMockPrisma()` duplicates.
- Single `createPrismaMock(seed?: PrismaMockSeed)` factory returns a `PrismaServiceMock` whose shape mirrors the Prisma surface that P5-003 → P5-007 read services and P7-004 → P7-007 write services actually use: `tenant`, `vendor`, `category`, `product`, each with `findUnique`, `findFirst`, `findMany`, `create`.
- **Call tracking** is first-class: every call to any method is recorded into `mock._calls.<table>.<method>`, the same shape the P7-004 → P7-007 evidence scripts relied on. Tests can assert on call counts, `where.id`, `where.slug`, `(tenantId, slug)` composite lookups, and `data` payload forwarding.
- **Find semantics** honor the same lookup patterns the production services rely on:
  - `findUnique({ where: { id } })` → id-keyed lookup.
  - `findUnique({ where: { slug } })` → slug-keyed lookup.
  - `findFirst({ where: { tenantId, slug } })` → composite-key lookup (proves the P7-006 / P7-007 category/product `(tenantId, slug)` unique behavior).
- **Create semantics** auto-increment ids (`tenant-1`, `vendor-2`, …), forward the `data` payload verbatim, stamp `createdAt`, and append to the in-memory collection so subsequent find calls see the new row (matches the real Prisma `@@unique([tenantId, slug])` propagation).
- Intentionally **does not** extend `PrismaClient` — these are unit tests, not database tests. A future integration test project can use `@nestjs/testing` + a test database without changing this utility.

### `backend/src/testing/test.module.ts` (new — P7-008 foundation)

- `createServiceTestHarness<T>(ServiceClass, seed?)` returns `{ module, service, prisma, reset, close }`.
- Uses `@nestjs/testing`'s `Test.createTestingModule({ providers: [ServiceClass, { provide: PrismaService, useValue: prisma }] }).compile()` so the real service runs through the real NestJS DI container with the mock PrismaService — no live database, no HTTP listener.
- `reset()` clears all `_calls` arrays so a single test can chain multiple scenarios (call → assert → reset → call again).
- `close()` releases the testing module via `moduleRef.close()` (safe in `afterEach`).
- Generic over the service class so it is reusable for any future service test, not just `TenantsService`.

### `backend/src/testing/test.utils.spec.ts` (new — the proof test)

- The test file is itself the deliverable: it proves the foundation works, not exhaustively tests any business service.
- **Section 1 — `createPrismaMock` unit tests (7 cases):**
  - starts with empty call logs and entity collections
  - seeds entities and `findUnique` by id returns the seed
  - `findUnique` by slug returns the seed
  - `findUnique` returns null when id unknown
  - `findFirst` honors composite `(tenantId, slug)` where
  - `create` stores the new entity and is visible to subsequent `findUnique`
  - tracks every call into `_calls` for later assertions
- **Section 2 — `createServiceTestHarness` + real `TenantsService` (5 cases):**
  - wires the real `TenantsService` into the test module with the mocked `PrismaService`
  - `TenantsService.create()` against a real NestJS testing module + mock Prisma (asserts `success()` envelope, `findUnique` pre-check, `create` payload)
  - `TenantsService.create()` throws `ConflictException` on duplicate slug via the **real** `@nestjs/common` exception class, and `create` is not called a second time
  - `TenantsService.findOne()` throws `NotFoundException` via the **real** exception class
  - `harness.reset()` clears the call log without dropping the mock's usability
- Final result: **12/12 tests pass** via `npm test`.
