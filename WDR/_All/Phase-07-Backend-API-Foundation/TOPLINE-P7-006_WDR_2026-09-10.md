## IMPLEMENTATION

### `backend/src/categories/dto/create-category.dto.ts` (new)

- `CreateCategoryDto` class-validator DTO mirroring `CreateVendorDto`/`CreateTenantDto`'s style.
- Required fields:
  - `tenantId` — non-empty string
  - `name` — 1–255 chars
  - `slug` — 1–255 chars, lowercase letters/digits/hyphens only (regex `/^[a-z0-9-]+$/`)
  - `status` — one of `ACTIVE`/`HIDDEN` (matches Prisma `CategoryStatus` enum)
- Optional fields:
  - `icon` — string, max 50 chars (matches Prisma `icon? @db.VarChar(50)`)
  - `parentId` — string (validated for existence and tenant-scope at service layer)
  - `sortOrder` — integer, `>= 0` (matches Prisma `sortOrder Int @default(0)`)
- `parentId`/`sortOrder`/`icon` were intentionally **not** subject to more
  elaborate DTO validation beyond their types because the corresponding
  cross-record checks (parent existence, tenant-scope of parent, duplicate
  `(tenantId, slug)`) are owned by the service layer — exactly as the
  Vendor/Service pattern does.

### `backend/src/categories/categories.service.ts` (modified)

- Added `create(dto: CreateCategoryDto)`:
  1. **Tenant existence check** — `prisma.tenant.findUnique({ where: { id: dto.tenantId } })`;
     throws `NotFoundException('Tenant not found')` if absent. Short-circuits
     before any category lookup/create.
  2. **Optional parent category check** — only if `dto.parentId !== undefined`:
     - `prisma.category.findUnique({ where: { id: dto.parentId } })` to verify
       the parent exists.
     - If the parent exists but belongs to a *different* tenant, throws
       `NotFoundException('Parent category not found')` (parent is effectively
       not visible to the requesting tenant).
     - Throws `NotFoundException('Parent category not found')` if absent.
  3. **Duplicate `(tenantId, slug)` check** — `prisma.category.findFirst({ where: { tenantId, slug } })`;
     throws `ConflictException('Category with slug "..." already exists for this tenant')` if found.
     Uses `findFirst` (not `findUnique`) because the unique is composite
     `[tenantId, slug]`, not a single field.
  4. **Create** — `prisma.category.create()` with a `select` limited to
     `id, tenantId, parentId, name, status, sortOrder, createdAt` (same shape
     as the existing `CategorySummaryDto` and the read-endpoint projection).
     `sortOrder ?? 0` so omitted `sortOrder` is forwarded to Prisma's
     `Int @default(0)` cleanly.
  5. Returns `success(category, { phase: 'P7-006' })`.
- Existing `findAll`/`findOne` read methods are unchanged.

### `backend/src/categories/categories.controller.ts` (modified)

- Added `POST /categories` → `@HttpCode(HttpStatus.CREATED)`
  `create(@Body() dto: CreateCategoryDto)`, mirroring `VendorsController.create()`.
- Existing `GET /categories` and `GET /categories/:id` are unchanged.

### `backend/src/categories/categories.module.ts`

- No change required — controller/service were already registered.

### `backend/scripts/test-category-create.js` (new)

- Mirrors `backend/scripts/test-vendor-create.js`'s real-service testing
  approach (the pattern the P7-004-R2/P7-005 audits required):
  - Imports the real `CreateCategoryDto` and `CategoriesService` from compiled
    `dist/` output — no mock/fallback class.
  - `createMockPrisma()` builds a call-tracking mock covering exactly the
    Prisma surface the service touches: `tenant.findUnique`,
    `category.findUnique`, `category.findFirst`, `category.create`. The mock
    stores the same fields the real `PrismaService` would return (including
    `slug` and `tenantId`) so the composite unique key can be exercised
    accurately.
  - **Validation tests (1–20)** — 20 cases: valid input, missing `tenantId`,
    missing `name`, empty `name`, name > 255 chars, missing `slug`, invalid
    slug characters, invalid status, valid `HIDDEN`/`ACTIVE` statuses, valid
    optional `icon`/`parentId`/`sortOrder`, negative `sortOrder`, icon > 50
    chars.
  - **Real-service tests (21–46)** — 26 cases exercising the real
    `CategoriesService.create()` against the call-tracking mock:
    - successful create — asserts the exact
      `tenant.findUnique` → `category.findFirst` (composite key) → `category.create`
      call sequence, response envelope, and `meta.phase = 'P7-006'`.
    - missing tenant — asserts a real `@nestjs/common NotFoundException` and
      that `category.findUnique` / `category.findFirst` / `category.create` are
      **all** never reached.
    - missing parent — asserts a real `NotFoundException` carrying a
      "Parent category" message, and that `category.findFirst` /
      `category.create` are never reached; only the parent lookup runs.
    - cross-tenant parent — asserts `NotFoundException` (parent not found in
      requesting tenant) and that `category.create` is not called.
    - duplicate `(tenantId, slug)` — asserts a real
      `@nestjs/common ConflictException` with an "already exists" message,
      that `category.create` is not called a second time, and that
      `category.findFirst` is still called on the duplicate attempt.
    - same slug across different tenants is **allowed** — proves the
      composite `[tenantId, slug]` unique key is honored, not a global
      slug-only uniqueness.
    - multiple distinct categories, optional `icon`/`sortOrder`
      pass-through, `sortOrder` defaults to 0 when omitted, validated DTO
      instance is accepted end-to-end, valid parent path wires
      `parentId` through.

Total: 46 assertions in 57 sub-asserts (some tests cover multiple
properties). Final runner reports **57 passed, 0 failed**.
