## IMPLEMENTATION

### `backend/src/vendors/dto/create-vendor.dto.ts` (new)

- `CreateVendorDto` class-validator DTO mirroring `CreateTenantDto`'s style.
- Fields: `tenantId` (required string), `name` (required, 1–255 chars), `slug`
  (required, lowercase/digits/hyphens only, 1–255 chars), `status` (required,
  one of `DRAFT`/`ACTIVE`/`SUSPENDED` — matches Prisma `VendorStatus` enum),
  `description` (optional string, max 2000 chars), `logo` (optional string,
  max 2048 chars).
- `ownerId` was intentionally omitted: it ties vendor creation to the `User`
  model, which borders on auth/RBAC — out of scope per the task's forbidden
  list.

### `backend/src/vendors/vendors.service.ts` (modified)

- Added `create(dto: CreateVendorDto)`:
  1. Tenant existence check — `prisma.tenant.findUnique({ where: { id: dto.tenantId } })`;
     throws `NotFoundException('Tenant not found')` if absent.
  2. Duplicate slug check — `prisma.vendor.findUnique({ where: { slug: dto.slug } })`;
     throws `ConflictException('Vendor with slug "..." already exists')` if found.
  3. Creates the vendor via `prisma.vendor.create()` with a `select` limited to
     `id, tenantId, name, status, createdAt` (same shape as `VendorSummaryDto`,
     matching the existing read-endpoint projection).
  4. Returns `success(vendor, { phase: 'P7-005' })`.
- Existing `findAll`/`findOne` read methods are unchanged.

### `backend/src/vendors/vendors.controller.ts` (modified)

- Added `POST /vendors` → `@HttpCode(HttpStatus.CREATED)` `create(@Body() dto: CreateVendorDto)`,
  mirroring `TenantsController.create()`.
- Existing `GET /vendors` and `GET /vendors/:id` are unchanged.

### `backend/src/vendors/vendors.module.ts`

- No change required — controller/service were already registered.

### `backend/scripts/test-vendor-create.js` (new)

- Mirrors `backend/scripts/test-tenant-create.js`'s real-service testing
  approach (the pattern the P7-004-R2 audit required):
  - Imports the real `CreateVendorDto` and `VendorsService` from compiled
    `dist/` output — no mock/fallback class.
  - `createMockPrisma()` builds a call-tracking mock covering exactly the
    Prisma surface the service touches: `tenant.findUnique`,
    `vendor.findUnique`, `vendor.create`.
  - Validation tests (1–10): valid input, missing `tenantId`/`name`, empty
    name, name length, invalid slug characters, invalid status, valid
    `DRAFT`/`SUSPENDED` statuses, valid optional `description`/`logo`.
  - Real-service tests (11–15): successful create asserts the exact
    `tenant.findUnique` → `vendor.findUnique` → `vendor.create` call sequence
    and response envelope; missing tenant asserts a real
    `@nestjs/common NotFoundException` and that `vendor.create()`/`vendor.findUnique()`
    are never reached; duplicate slug asserts a real `ConflictException` and
    that `vendor.create()` is not called a second time; multiple distinct
    vendors can be created; a `plainToInstance(CreateVendorDto, …)` instance
    is accepted end-to-end.
