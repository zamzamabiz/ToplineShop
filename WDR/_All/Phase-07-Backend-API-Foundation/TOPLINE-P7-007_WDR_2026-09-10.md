## IMPLEMENTATION

### `backend/src/products/dto/create-product.dto.ts` (new)

- `CreateProductDto` class-validator DTO following the `CreateVendorDto` /
  `CreateTenantDto` / `CreateCategoryDto` style with product-specific
  numeric/currency/stock handling.
- Required fields:
  - `tenantId` — non-empty string
  - `vendorId` — non-empty string
  - `categoryId` — non-empty string
  - `name` — 1–255 chars
  - `slug` — 1–255 chars, lowercase letters/digits/hyphens only (regex `/^[a-z0-9-]+$/`)
  - `basePrice` — `@IsNumber({ allowNaN: false, allowInfinity: false })` with `@Min(0)`. JSON-decoded numeric values land here as JS numbers; the DTO rejects strings, NaN, ±Infinity, and negatives, so `Prisma.product.create()` always receives a real non-negative finite number for its `Decimal(19,4)` column.
  - `status` — one of `DRAFT`/`ACTIVE`/`ARCHIVED` (matches Prisma `ProductStatus` enum)
- Optional fields:
  - `description` — string, max 2000 chars (matches vendor's `description` max)
  - `currency` — string matching `/^[A-Z]{3}$/` (3-letter uppercase ISO 4217). Service layer defaults to `"NGN"` if omitted, matching Prisma's `@default("NGN")`.
  - `inStock` — boolean, service layer defaults to `true`, matching Prisma's `@default(true)`.
- Cross-record checks (tenant/vendor/category existence, vendor/category
  tenant-scope, duplicate `(tenantId, slug)`) are owned by the service
  layer — exactly as the Vendor/Category/Service pattern does. This keeps
  DTO validation focused on shape/type and lets the service own the
  relational safety.
- Zero `basePrice` is intentionally allowed at the DTO level — free
  products (promotions, samples) are a legitimate marketplace case, and
  the relational rules live in the service.

### `backend/src/products/products.service.ts` (modified)

- Added `create(dto: CreateProductDto)`:
  1. **Tenant existence check** — `prisma.tenant.findUnique({ where: { id: dto.tenantId } })`;
     throws `NotFoundException('Tenant not found')` if absent. Short-circuits
     before any vendor/category lookup/create.
  2. **Vendor existence + tenant-scope check** —
     `prisma.vendor.findUnique({ where: { id: dto.vendorId }, select: { id, tenantId } })`;
     throws `NotFoundException('Vendor not found')` if absent **or** if
     `vendor.tenantId !== dto.tenantId` (cross-tenant vendor is rejected
     with the same "Vendor not found" message to avoid leaking cross-tenant
     existence). Short-circuits before the category lookup.
  3. **Category existence + tenant-scope check** —
     `prisma.category.findUnique({ where: { id: dto.categoryId }, select: { id, tenantId } })`;
     throws `NotFoundException('Category not found')` if absent or
     cross-tenant (same anti-leak rationale).
  4. **Duplicate `(tenantId, slug)` check** — `prisma.product.findFirst({ where: { tenantId, slug } })`;
     throws `ConflictException('Product with slug "..." already exists for this tenant')` if found.
     Uses `findFirst` (not `findUnique`) because the unique is composite
     `[tenantId, slug]`.
  5. **Create** — `prisma.product.create()` with a `select` limited to
     `id, tenantId, vendorId, categoryId, name, status, createdAt` (same
     shape as the existing `ProductSummaryDto` and the read-endpoint
     projection). `currency ?? 'NGN'` and `inStock ?? true` mirror the
     Prisma column defaults so the service is the single source of truth
     for "what does the row look like if the DTO omits these".
  6. Returns `success(product, { phase: 'P7-007' })`.
- Existing `findAll`/`findOne` read methods are unchanged.

### `backend/src/products/products.controller.ts` (modified)

### `backend/scripts/test-product-create.js` (new)

- Mirrors `backend/scripts/test-vendor-create.js` and
  `backend/scripts/test-category-create.js`'s real-service testing
  approach (the pattern the P7-004-R2/P7-005/P7-006 audits required):
  - Imports the real `CreateProductDto` and `ProductsService` from compiled
    `dist/` output — no mock/fallback class.
  - `createMockPrisma()` builds a call-tracking mock covering exactly the
    Prisma surface the service touches: `tenant.findUnique`,
    `vendor.findUnique`, `category.findUnique`, `product.findFirst`,
    `product.create`. The mock stores the same fields the real
    `PrismaService` would return (including `slug` and `tenantId`) so the
    composite unique key can be exercised accurately.
  - **Validation tests (1–36)** — 36 cases: valid minimum, missing
    `tenantId`/`vendorId`/`categoryId`/`name`/`slug`/`basePrice`, empty
    name, name > 255 chars, invalid slug, `basePrice` as string, negative
    `basePrice`, NaN `basePrice`, zero `basePrice` allowed, invalid status,
    valid `DRAFT`/`ACTIVE`/`ARCHIVED`, missing currency allowed,
    lowercase/4-letter currency rejected, valid 3-letter uppercase
    currency, valid description, description > 2000 chars, `inStock=false`,
    `inStock` as string rejected.
  - **Real-service tests (37–55)** — 19 cases exercising the real
    `ProductsService.create()` against the call-tracking mock:
    - successful create — asserts the exact
      `tenant.findUnique` → `vendor.findUnique` → `category.findUnique` →
      `product.findFirst` (composite key) → `product.create` call
      sequence, response envelope, and `meta.phase = 'P7-007'`.
    - successful create with all optional fields —
      `basePrice`/`currency`/`inStock`/`description` forwarded to
      `prisma.product.create()`.
    - `currency` defaults to `"NGN"` when omitted.
    - `inStock` defaults to `true` when omitted.
    - missing tenant — asserts a real `@nestjs/common NotFoundException`
      and that `vendor.findUnique` / `category.findUnique` /
      `product.findFirst` / `product.create` are **all** never reached.
    - missing vendor — asserts a real `NotFoundException` carrying a
      "Vendor not found" message; never reaches category or create.
    - cross-tenant vendor — asserts `NotFoundException`; never reaches
      `product.create`.
    - missing category — asserts a real `NotFoundException` carrying a
      "Category not found" message; never reaches `product.create`.
    - cross-tenant category — asserts `NotFoundException`; never reaches
      `product.create`.
    - duplicate `(tenantId, slug)` — asserts a real
      `@nestjs/common ConflictException` with an "already exists" message,
      that `product.create` is not called a second time, and that
      `product.findFirst` is still called on the duplicate attempt.
    - same slug across different tenants is **allowed** — proves the
      composite `[tenantId, slug]` unique key is honored, not a global
      slug uniqueness.
    - multiple distinct products, validated DTO instance is accepted
      end-to-end, high-precision `basePrice` is forwarded.

Total: 55 assertions in 82 sub-asserts (some tests cover multiple
properties). Final runner reports **82 passed, 0 failed**.
