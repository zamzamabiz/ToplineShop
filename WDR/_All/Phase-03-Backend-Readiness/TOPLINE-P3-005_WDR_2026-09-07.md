## AUTH/RBAC DESIGN PRINCIPLES SUMMARY

13 principles established:
1. Tenant-aware
2. Permission-based
3. Module-aware
4. Multi-business capable
5. No single-business hardcoding
6. Owner/Admin powerful but audited
7. Vendor isolation
8. Customer boundary
9. Wholesale buyer approval
10. Financial safety
11. AI governance
12. Backend-enforced
13. Future-proof

## TENANT/MODULE ACCESS SUMMARY

- Access = TenantMembership × Role × Permission × TenantModule
- Module must be enabled for tenant
- Role must be assigned
- Membership must be active
- User must be active
- Owner/Admin can see all tenants (audit-logged)
- Vendor users restricted to assigned vendor(s)
- Wholesale buyers require explicit approval

## PERMISSION DESIGN SUMMARY

**Format**: `module.resource.action`

**Actions**: read, create, update, delete, approve, reject, export, manage, override

**Risk Levels**:
- LOW: read, create
- MEDIUM: update, reject
- HIGH: delete, approve, export, manage
- CRITICAL: override

**Modules covered**: marketplace, vendor, b2b, admin, owner, financial, AI, future (CRM, ERP, FMCG, healthcare, education, property)

## FINANCIAL SAFETY RBAC SUMMARY

- Financial permissions: payments, refunds, settlements, ledger, commissions
- Approval required for: payment processing (above threshold), refund approval, settlement execution, ledger adjustment, commission override, payout processing
- Maker-checker pattern for high-risk actions
- All financial actions audit-logged
- Payment provider integration deferred

## AUDIT LOGGING POLICY SUMMARY

**Events logged**: Security, Identity, Membership, Role, Permission, Tenant, Module, Vendor, Wholesale, Product, Order, Financial, Export, AI, Admin Override

**Rules**:
- Immutable
- Minimum 1 year retention (7 years for financial)
- Searchable by tenant, user, action, date range
- Owner-only access
- Export logging required

## AI GOVERNANCE RBAC SUMMARY

**AI Permissions**: suggestions.read, suggestions.approve, classification.read, classification.execute, proposals.read, proposals.approve, reports.read

**Safety Rules**:
- AI may suggest, classify, summarize, recommend, propose
- AI must not directly approve financial, legal, tax, destructive actions
- Human approval required for all AI action proposals
- Tenant isolation and module permissions enforced
- All AI actions audit-logged

## FUTURE MODULE ROLE SUPPORT SUMMARY

**Extension Pattern**: Register module → Define roles → Define permissions → Link via RolePermission → Enable via TenantModule → Assign via TenantMembershipRole

**Compatibility**: Marketplace + B2B + CRM + ERP core modules compatible. FMCG, Healthcare, Education, Property, Consulting depend on CRM.

## AUTH TECHNOLOGY OPTIONS SUMMARY

| Option | Pros | Cons | SaaS Suitability | Recommendation |
|--------|------|------|------------------|----------------|
| NextAuth.js | Next.js native, fast | Limited multi-tenant | LOW | Not recommended |
| Custom JWT + Passport | Full control, NestJS-native | More effort | HIGH | Recommended |
| External Provider | Battle-tested, managed | Vendor dependency | VERY HIGH | Future consideration |

**Recommended**: Option B (Custom JWT + NestJS Passport) for launch, Option C for Phase 7+.
