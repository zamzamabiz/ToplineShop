## BACKEND STACK RECOMMENDATION SUMMARY

**Recommended: Option C — Hybrid (Next.js Frontend + NestJS Backend)**

- Frontend stays Next.js (proven, 17 routes working)
- Backend is independent NestJS service
- Clean API contract between them
- Future-proof for multi-vendor SaaS, B2B, AI features
- Independent scaling and deployment

## DATABASE DIRECTION SUMMARY

- **Primary DB**: PostgreSQL
- **ORM**: Prisma
- **Core domains**: Users, Vendors, Products, Categories, Cart, Orders, Payments, Commissions, Settlements, B2B RFQ, Audit Logs, Notifications
- **Environments**: Dev, Staging, Production separation
- **Seeds**: Dev seed matches current mock data

## AUTH/RBAC PLAN SUMMARY

- **Auth**: NextAuth.js (Auth.js) or custom JWT
- **Roles**: Guest, Customer, Wholesale Buyer, Vendor User, Vendor Admin, Platform Admin, Owner, Support
- **Safety**: Owner-only financial controls, vendor isolation, audit logging

## API BOUNDARY PLAN SUMMARY

- RESTful API with versioning (`/api/v1/*`)
- 14 API groups planned (Auth, Users, Categories, Products, Vendors, Cart, Orders, Payments, RFQ, Admin, Owner, Audit, Notifications, AI)
- Phased implementation: Auth/Users/Categories in Phase 7, Commerce in Phase 8, Payments in Phase 9

## PAYMENT/CHECKOUT SAFETY POLICY SUMMARY

- No payment until product/order/cart/auth are real and tested
- No fake financial metrics
- All money operations require audit logs
- Refund/settlement/payment must be Owner-approved
